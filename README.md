**LivePaint** — небольшое приложение для объяснений, демонстраций и быстрых
пометок прямо на экране. Окна под рисунками продолжают работать: это прозрачный
Wayland-оверлей, а не редактор скриншотов и не замороженное изображение рабочего стола.

Компактная панель в стиле Excalidraw, без Electron и тяжёлых визуальных эффектов.

## Возможности

- Перо, линия, стрелка, прямоугольник и эллипс.
- Шесть цветов, три толщины и ластик для удаления целых штрихов.
- Отмена и повтор действий; история до 64 шагов.
- Ровные углы, квадраты и круги с зажатым `Shift`.
- **Рисование ↔ рабочий стол:** переключение между захватом мыши и пропуском кликов.
- Скрытие без потери рисунков, пока приложение остаётся запущенным.
- Управление с панели, клавиатуры или командами из терминала.
- Один экземпляр на Wayland-дисплей: повторный запуск переключает видимость.

## Требования

| Компонент            | Что нужно                                                   |
| -------------------- | ----------------------------------------------------------- |
| Система              | Linux; проверено на Arch Linux + Hyprland                   |
| Сессия               | **Wayland** и поддержка `wlr-layer-shell` композитором      |
| Графика              | Видеокарта и драйвер с поддержкой **Vulkan**                |
| Для сборки           | Актуальный стабильный Rust/Cargo, C toolchain, `pkg-config` |
| Системные библиотеки | Wayland, xkbcommon, Vulkan loader                           |

Это приложение для Hyprland/Wayland, а не обычное окно X11/XWayland.
Другие композиторы с layer-shell могут подойти, но здесь не проверялись.
OpenGL-бэкенд не включён: он не гарантирует необходимую прозрачность Wayland-поверхности.

## Установка

### 1. Подготовь зависимости

На Arch Linux:

```sh
sudo pacman -S --needed base-devel git pkgconf wayland libxkbcommon vulkan-icd-loader
```

Если Rust ещё не установлен:

```sh
sudo pacman -S --needed rust
```

Если уже используешь **rustup**, оставь его и используй актуальный stable toolchain;
устанавливать пакет `rust` параллельно не нужно.

Также нужен Vulkan-драйвер **для твоей видеокарты**, а не все драйверы сразу:

| Видеокарта                | Драйвер                                                                   |
| ------------------------- | ------------------------------------------------------------------------- |
| Intel с поддержкой Vulkan | `vulkan-intel`                                                            |
| AMD с поддержкой Vulkan   | `vulkan-radeon`                                                           |
| NVIDIA                    | Совместимый с видеокартой драйвер NVIDIA и соответствующий `nvidia-utils` |

Если Vulkan-приложения у тебя уже работают, дополнительная установка драйвера
может не понадобиться. `vulkan-icd-loader` — загрузчик, он не заменяет драйвер GPU.

### 2. Склонируй и собери

Замени `YOUR_USERNAME` на владельца репозитория. Если репозиторий называется не
`livepaint`, замени также его имя и папку в команде `cd`.

```sh
git clone https://github.com/WhyDojo/livepaint.git
cd livepaint
cargo build --release --locked
```

Первая сборка скачает Rust-зависимости и создаст локальный кэш в `target/`.
Это может занять несколько минут и заметно больше места, чем готовое приложение.
`Cargo.lock` фиксирует версии зависимостей и хранится в репозитории.

### 3. Установи в домашнюю папку

```sh
make install
```

**Без `sudo`.** По умолчанию устанавливаются только эти файлы:

```text
~/.local/bin/livepaint
~/.local/share/applications/livepaint.desktop
~/.local/share/icons/hicolor/scalable/apps/livepaint.svg
```

Конфиг Hyprland, автозапуск и настройки драйверов установщик не изменяет.
Для команды `livepaint` из терминала и запуска через desktop-файл каталог
`~/.local/bin` должен быть в `PATH` сессии. В примерах биндов ниже указан путь
к бинарнику, поэтому они не зависят от этого.

> Можно обойтись без установки: запускай `./target/release/livepaint` из папки
> проекта. Но такой путь перестанет работать после полной очистки `target/`.

## Запуск

Запускай из обычной пользовательской сессии Hyprland, **не через `sudo`**:

```sh
~/.local/bin/livepaint
```

Первый вызов показывает оверлей на активном мониторе Hyprland. Следующий —
скрывает его, ещё один — показывает снова. Автозапуск для этого не нужен.

**Быстрый сценарий:** запусти → рисуй мышью → нажми `Tab`, чтобы работать с окнами
под рисунком → нажми перо на панели, чтобы вернуться → нажми `Esc`, чтобы скрыть.

### Выбор монитора

```sh
hyprctl monitors
~/.local/bin/livepaint --output DP-1
```

`DP-1` — пример: возьми имя из вывода `hyprctl monitors`. Выбор применяется только
при запуске нового экземпляра. Чтобы сменить экран, сначала заверши приложение
командой `quit`, затем запусти на нужном мониторе. Текущие рисунки при этом удалятся.

## Хоткеи Hyprland

Проверь, что выбранные сочетания свободны в твоём конфиге. Если бинды LivePaint
уже есть, **обнови их**, а не добавляй второй набор для тех же сочетаний.
Уже работающие сочетания можно оставить как есть: ниже только примеры настройки.

### Обычный конфиг `.conf`

Добавь в свой файл биндов или `~/.config/hypr/hyprland.conf`:

```ini
$livepaint = ~/.local/bin/livepaint
bind = SUPER SHIFT, D, exec, $livepaint toggle
bind = SUPER SHIFT, A, exec, $livepaint passthrough
bind = SUPER SHIFT, C, exec, $livepaint clear
```

Этот же пример находится в [`contrib/hyprland.conf`](contrib/hyprland.conf).
Его можно подключить через `source`, указав **свой** путь к клону репозитория.

### Lua-конфиг с `hl.bind`

Если твой Hyprland использует Lua API `hl.bind` / `hl.dsp.exec_cmd`, добавь
в загружаемый модуль биндов, например `~/.config/hypr/modules/keybindings.lua`:

```lua
local livepaint = os.getenv("HOME") .. "/.local/bin/livepaint"

hl.bind("SUPER + SHIFT + D", hl.dsp.exec_cmd(livepaint .. " toggle"))
hl.bind("SUPER + SHIFT + A", hl.dsp.exec_cmd(livepaint .. " passthrough"))
hl.bind("SUPER + SHIFT + C", hl.dsp.exec_cmd(livepaint .. " clear"))
```

Это альтернативные примеры для разных форматов конфига: используй подходящий
своему Hyprland, не нужно добавлять оба.

| Сочетание       | Действие                      |
| --------------- | ----------------------------- |
| `Super+Shift+D` | Запустить / показать / скрыть |
| `Super+Shift+A` | Рисование ↔ пропуск кликов    |
| `Super+Shift+C` | Очистить рисунки              |

Применить конфиг:

```sh
hyprctl reload
```

## Управление

На панели находятся инструменты рисования, переключатель работы с рабочим столом,
цвет и толщина. В меню **«…»** — Undo, Redo, Clear canvas, Shortcuts, Hide и Quit.
Назначения кнопок видны при наведении.

| Клавиши                     | Действие                                               |
| --------------------------- | ------------------------------------------------------ |
| `P` / `L` / `A`             | Перо / линия / стрелка                                 |
| `R` / `O` / `E`             | Прямоугольник / эллипс / ластик                        |
| `1`–`6`                     | Цвет                                                   |
| `[` / `]` или колесо        | Толщина                                                |
| `Shift` + рисование         | Линия с шагом угла 45°, квадрат или круг               |
| `Ctrl+Z`                    | Отменить                                               |
| `Ctrl+Shift+Z` или `Ctrl+Y` | Повторить                                              |
| `Ctrl+Backspace`            | Очистить; действие можно отменить                      |
| Правая кнопка мыши          | Временный ластик                                       |
| `Tab`                       | Перейти к работе с приложениями под оверлеем           |
| `Esc`                       | Скрыть; при открытой справке сначала закрывает справку |
| `Ctrl+Q`                    | Завершить приложение                                   |
| `F1`                        | Справка                                                |

Хоткеи инструментов привязаны к физическим клавишам и работают в том числе
в русской раскладке. Ластик удаляет целые штрихи, а не отдельные пиксели.

> **Как вернуться из пропуска кликов?** В этом режиме клавиатура принадлежит
> приложениям под оверлеем, поэтому второй `Tab` не возвращает рисование.
> Нажми перо на панели или используй глобальный хоткей Hyprland.
> Панель и её всплывающие блоки остаются кликабельными.

### Команды терминала

После установки, если `~/.local/bin` есть в `PATH`:

```sh
livepaint                 # Запустить или переключить видимость
livepaint show            # Показать; запускает приложение, если оно не запущено
livepaint hide            # Скрыть, сохранив рисунки в памяти
livepaint passthrough     # Переключить пропуск кликов
livepaint clear           # Очистить
livepaint undo            # Отменить
livepaint redo            # Повторить
livepaint quit            # Завершить и удалить рисунки из памяти
livepaint --help          # Справка CLI
```

Команды, кроме `toggle` и `show`, требуют запущенный экземпляр. Они передаются
через локальный Unix-сокет в `$XDG_RUNTIME_DIR`; сетевой сервер для этого не нужен.

## Ограничения

- Один выбранный монитор за запуск; автоматического переноса между экранами нет.
- Рисунки привязаны к экрану, а не к содержимому окон: не следуют за прокруткой.
- Поддерживаются мышь и тачпад; чувствительности к нажиму стилуса пока нет.
- Нет текстовых аннотаций, экспорта и сохранения рисунков между запусками.
- **Hide / `Esc` сохраняют рисунки в памяти. Quit / `Ctrl+Q` удаляют их.**
- При захвате всего монитора оверлей может попадать в запись или демонстрацию экрана.

## Производительность

Штрихи рисуются на GPU через wgpu/Vulkan. Сглаживание линий и эллипсов реализовано
в WGSL; для штрихов используется один instanced draw call, без MSAA.
Цикл событий спит в простое, а во время рисования кадры ограничены Wayland frame
callbacks. При скрытии поверхность снимается с экрана. История разделяет данные
штрихов через `Arc`, не копируя все точки на каждый шаг.

Приложение запрашивает энергоэффективный GPU (`LowPower`). Конкретная задержка,
потребление памяти и производительность зависят от драйвера, разрешения и числа
штрихов; универсальных гарантий FPS для любого ноутбука нет.

## Решение проблем

**Не найден Vulkan GPU / ошибка драйвера.** Проверь драйвер своей видеокарты.
Для диагностики можно установить `vulkan-tools` и выполнить `vulkaninfo --summary`.
Просто установить loader недостаточно: нужен работающий Vulkan-драйвер.

**Cannot connect to Wayland / не заданы переменные сессии.** Запускай из терминала
внутри своей Wayland-сессии, без `sudo`. Приложению нужны `WAYLAND_DISPLAY` и
`XDG_RUNTIME_DIR`. Из обычной TTY без подключения к графической сессии оно не запустится.

**Команда `livepaint` не найдена.** Используй `~/.local/bin/livepaint` после установки
или `./target/release/livepaint` из папки проекта. При необходимости добавь
`~/.local/bin` в `PATH` своей оболочки и графической сессии.

**Горячие клавиши не срабатывают.** Проверь путь к установленному бинарнику,
формат конфига, конфликты сочетаний и результат `hyprctl configerrors` после reload.

**После пересборки осталась старая панель.** Работающий экземпляр не обновляется
автоматически. Заверши его и запусти снова; сначала учти, что рисунки будут удалены.

## Разработка

```sh
make check
```

Запускает `cargo fmt --check`, Clippy с запретом предупреждений и тесты.

```text
src/app.rs       Wayland, ввод и цикл событий
src/drawing.rs   Документ, геометрия и история
src/renderer.rs  GPU-рендерер
src/ink.wgsl     Шейдер штрихов
src/ui.rs        Компактная панель и всплывающие блоки
src/ipc.rs       Управление запущенным экземпляром
contrib/        Пример биндов, desktop-файл и значок
```

### Почему папка проекта больше самого приложения?

`target/` — локальные результаты сборки: зависимости, отладочная информация,
тесты и промежуточные файлы. Это **не исходники**. Папка может занимать гигабайты,
но она исключена из Git через `.gitignore` и не нужна пользователю готового бинарника.

`cargo clean` удаляет этот кэш **вместе с `target/release/livepaint`**. Если приложение
установлено через `make install`, копия в `~/.local/bin/` останется на месте.
После очистки следующая сборка будет дольше. Удалять кэш ради публикации не нужно.

Подробно о том, что отправлять в репозиторий и как создать первый commit:
**[Публикация на GitHub](docs/PUBLISHING.md)**.

## Удаление

Заверши приложение, затем из папки проекта выполни:

```sh
make uninstall
```

Это удалит установленные через Makefile бинарник, desktop-файл и значок
из `~/.local`. Добавленные вручную бинды нужно убрать из конфига отдельно.
